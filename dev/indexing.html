Indexing a Directory#

Use arlmet.index() to find the ARL files that cover a time window by what their headers say, not by how they are named. Each file’s index records hold its valid times, the model that wrote it (the source), and its grid. index reads them once for a whole folder and keeps them in a small table. covering() then returns the files for a window, and missing() the hours no file holds.

import arlmet

idx = arlmet.index("hrrr")
files = idx.covering("2021-01-14 06:00", "2021-01-15 06:00")

A program that finds files by a name pattern (%Y%m%d_%H) finds nothing when the pattern is wrong or the archive is renamed, and cannot tell two products named alike apart. The index needs only the folder.

An example#

The examples on this page use four small files written with arlmet.write_dataset(): six hourly time steps each, from 2024-07-01 00:00 to 23:00, named after their first hour. Any names would do.

In [1]: import tempfile

In [2]: from pathlib import Path

In [3]: import numpy as np

In [4]: import pandas as pd

In [5]: import xarray as xr

In [6]: import arlmet

In [7]: folder = Path(tempfile.mkdtemp()) / "met"

In [8]: folder.mkdir()

In [9]: grid = xr.Variable((), 0, attrs={
   ...:     "nx": 20, "ny": 20, "pole_lat": 90.0, "pole_lon": 0.0,
   ...:     "tangent_lat": 1.0, "tangent_lon": 1.0, "grid_size": 0.0,
   ...:     "orientation": 0.0, "cone_angle": 0.0, "sync_x": 1.0, "sync_y": 1.0,
   ...:     "sync_lat": 30.0, "sync_lon": -120.0,
   ...: })
   ...: 

In [10]: surface = arlmet.SigmaAxis(levels=[1.0])

In [11]: day = xr.Dataset(
   ....:     {"PRSS": (("time", "lat", "lon"), np.full((24, 20, 20), 850.0, "float32"))},
   ....:     coords={"time": pd.date_range("2024-07-01", periods=24, freq="h"), "arl_grid": grid},
   ....:     attrs={"source": "TEST"},
   ....: )
   ....: 

In [12]: for first in range(0, 24, 6):
   ....:     block = day.isel(time=slice(first, first + 6))
   ....:     arlmet.write_dataset(block, folder / f"20240701_{first:02d}", vertical_axis=surface)
   ....: 

In [13]: idx = arlmet.index(folder)

In [14]: idx.table[["source", "start", "end", "step"]]
Out[14]: 
  source               start                 end            step
0   TEST 2024-07-01 00:00:00 2024-07-01 05:00:00 0 days 01:00:00
1   TEST 2024-07-01 06:00:00 2024-07-01 11:00:00 0 days 01:00:00
2   TEST 2024-07-01 12:00:00 2024-07-01 17:00:00 0 days 01:00:00
3   TEST 2024-07-01 18:00:00 2024-07-01 23:00:00 0 days 01:00:00

table has one row per file: its path, its source, a short description of its grid, its first and last valid time (start and end), the time between its valid times (step), and an error column, empty for a file that can be used.

Finding the files for a window#

HYSPLIT interpolates between the valid times around each moment of a run, so a window needs every valid time from the one at or before its start to the one at or after its end. covering() returns the files that hold them, in time order:

In [15]: [p.name for p in idx.covering("2024-07-01 05:30", "2024-07-01 12:00")]
Out[15]: ['20240701_00', '20240701_06', '20240701_12']

The window starts at 05:30, so it needs 05:00, which is in the first file, and it ends at 12:00, which is in the third. A window from 06:00 to 11:00 needs only the second file.

The valid times are expected every step, the most common spacing between the valid times of the folder. When a file is missing, missing() lists the times no file holds, and covering raises ValueError with them:

In [16]: (folder / "20240701_06").unlink()

In [17]: idx = arlmet.index(folder)

In [18]: idx.missing("2024-07-01 05:30", "2024-07-01 08:00")
Out[18]: 
[Timestamp('2024-07-01 06:00:00'),
 Timestamp('2024-07-01 07:00:00'),
 Timestamp('2024-07-01 08:00:00')]

In [19]: try:
   ....:     idx.covering("2024-07-01 05:30", "2024-07-01 08:00")
   ....: except ValueError as exc:
   ....:     print(exc)
   ....: 
No file in /tmp/tmp8rl73gwc/met holds 2024-07-01 06:00, 2024-07-01 07:00, 2024-07-01 08:00, which 2024-07-01 05:00 to 2024-07-01 08:00 needs.

Times past the last file or before the first count as missing in the same way, one every step.

When two files hold the same valid time (a re-download kept under a new name, an older copy kept beside a newer one), covering raises ValueError and names both files, rather than choosing one. Move one of them out of the folder. missing does not list such a time: it is held, twice.

Which files are read#

  • The folder’s own files, or with recursive=True every folder below it. Archives come in two layouts. A plain copy of NOAA’s archive keeps files in YYYY/MM/ folders (hrrr/2021/01/20210114_00-05_hrrr): index it with recursive=True. A shared archive often keeps one flat folder of links into such a tree: index that folder as it is, without recursive.

  • Links to files are followed, and each real file is one row, shown by its real path, so a link and the file it points to, or two links to one file, never count as two files. A link whose target is gone, or a loop of links, is a row with the reason in error. Links to folders are not followed.

  • Subfolders are read in full with recursive=True, old copies included. An archive that keeps superseded files in a subfolder such as deprecated/ holds two files for those hours, and covering raises for them. Index the folder of live files instead (a year, or the flat folder of links), or the archive without recursive.

  • Hidden files and folders and backup copies are skipped: names that start with . (arl-met’s own partial outputs and the cache file) or end in ~.

  • Every other file is kept in the table. One that is not ARL, is cut short, holds no time step, or whose time steps are not evenly spaced (HYSPLIT stops where the spacing changes) gets the reason in error, and covering does not use it:

    bad = idx.table[idx.table["error"] != ""]

  • Opening a file is all that is checked. A time step written partway, or a record overwritten with other bytes, opens cleanly. Use arlmet.File.check() on the files covering returns to find those (see Checking Files).

Opening a file may warn: a time step that some NOAA HRRR files repeat byte for byte is read once, with an arlmet.ARLFormatWarning.

The cache#

The table is saved to a CSV file, so the files are opened only once. A later call to index lists the folder, reads again only the files that are new or whose size or modification time changed, and drops the files that are gone. cache says where it is:

  • .arlmet-index.csv in the folder itself, when you can write to it (.arlmet-index-recursive.csv for a recursive index);

  • otherwise, as for a shared read-only archive, a file named after the folder in $ARLMET_CACHE_DIR, or in the user cache folder when that variable is not set: $XDG_CACHE_HOME/arlmet/index (~/.cache/arlmet/index) on Linux, ~/Library/Caches/arlmet/index on macOS, %LOCALAPPDATA%\arlmet\index on Windows.

Pass cache_dir= to choose the folder yourself:

idx = arlmet.index("/archive/hrrr", cache_dir="caches")

How long it takes#

Opening a file reads one index record per time step, and files are opened 16 at a time, since on a network filesystem each one mostly waits on its reads. The first call on a large archive is slow. On two archives of about 16,000 six-hour HRRR files it took 10 minutes on a fast filesystem and 44 minutes on a busy shared one (where one file at a time would have taken about 11 hours). A later call only lists the folder and compares sizes and times: 4 to 34 seconds there. The cache is saved every 500 files, so an interrupted first call resumes where it stopped.
