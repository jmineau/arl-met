Developer notes#

Reference material for people changing arl-met itself. The rules a change must keep (the ARL format rules and the design invariants) and the commands are in AGENTS.md; how to send a change is in Contributing.

HYSPLIT routines arl-met mirrors#

arl-met follows HYSPLIT’s own reader and writer wherever the format leaves room for choice. The Fortran routines it matches:

HYSPLIT

What it does

In arl-met

pakout / pakinp

pack and unpack one field as byte differences; compute the checksum

arlmet.pack(), arlmet.unpack(), arlmet.calculate_checksum()

pakrec / pakndx

write records and the index record; the checksum table is reset to 0 at each time step and filled only for the records packed

arlmet.DataRecord.verify_checksum() treats a stored 0 as “none”

metinp

read a met file; never compares checksums

arlmet.File.check() reads headers only

metset.f

read the 12 projection values raw (12F7.0)

read and written raw too; only arlmet.Grid.calculate_coords() wraps longitudes

gblset / gbl2xy

place a longitude on a lat/lon grid: in 0-360, measured from sync_lon, unless sync_lon < 0 <= pole_lon (PRIME)

arlmet.Grid.subset() writes a crop as xtrct_grid does: sync_* its first cell with sync_lon in 0-360, pole_* its last

stlmbr / stcm1p (set up in metini.f)

the map projection of a projected grid: cone_angle alone picks polar stereographic (±90), Mercator (0) or a Lambert cone tangent there; grid_size holds at the reference latitude, tangent_lat

arlmet.Projection.params: lat_ts, or a Lambert k_0 that makes the scale 1 at tangent_lat; agrees with the compiled routines within 0.001 cells on HRRR, NAM, NARR, NAMS and WRF files

prfcom

choose the vertical conversion from the vertical flag

arlmet.VerticalAxis.from_flag() and its subclasses

prfsig / prfecm

the sigma (flag 1, and flag 5 without WRF’s hybrid coefficients) and hybrid (flag 4) profiles: heights from the ground (PRSS, T02M) with the virtual temperature; prfsig takes each level’s pressure from PRES when the file has it (ZFLG), prfecm always from the levels; ln p linear in height

the column in ops/sample.py and arlmet.z_agl(), through vertical._hysplit_z_agl; on two HRRR columns it agrees with the compiled prfsig within 0.006 hPa

prfprs

the pressure-level (flag 2) profile: heights from HGTS, the ground (SHGT, PRSS, T02M, U10M) at the bottom, levels at or below the ground skipped; ln p linear in height

the column in ops/sample.py; TEMP and winds agree with the compiled prfprs within 0.001 on NAM12 and GDAS columns, pressure within 0.0006 hPa (float32 rounding of ln p)

prfwrf

the WRF (flag 5) profile: pressure from the PRES field, heights from WRF’s hybrid coefficients (read from a side file, hybrid_wrfvcoords.txt)

not used: the coefficients are not in the ARL file, so arlmet.WrfAxis files take the prfsig path, pressure from PRES

xtrct_grid.f

crop a met file to a grid window

arlmet.Grid.window_from_bbox(), arlmet.extract_subset() (tests/test_subset_slow.py compares the two on real files). The same cells, but a projected crop keeps the source’s sync point, where xtrct_grid writes the corner cell’s latitude and longitude to 0.01 degree and so moves its crop by up to 0.15 cells (arlmet.Grid.subset())

Vertical-axis conversions#

Each subclass of arlmet.VerticalAxis converts its levels with keyword-only inputs (to_pressure(*, surface_pressure=None) and to_height_agl(*, surface_pressure=None, temperature=None, pressure=None, hgts=None, terrain=None)), uses only the ones its coordinate system needs, and raises ValueError naming a missing one.

Flag

Class

to_pressure

to_height_agl

1

SigmaAxis

offset + (surface_pressure - offset) * sigma (nominal; a file’s PRES is the real pressure)

hypsometric, from surface_pressure (PRSS) through pressure (PRES) when given, else the nominal pressure, with temperature

2

PressureAxis

the stored levels

hgts - terrain (HGTS minus SHGT)

3

TerrainAxis

raises ValueError (no pressure coordinate)

the stored levels (already above ground)

4

HybridAxis

surface_pressure * sigma + floor(level); the first level is the surface

hypsometric, as for flag 1

5

WrfAxis

raises ValueError (needs WRF’s hybrid coefficients; use PRES)

hypsometric, as for flag 1 with pressure (PRES); the ground temperature is the first level’s brought down from its eta

Any other flag raises ValueError in from_flag.

Flag 5 is what HYSPLIT’s arw2arl writes for a WRF run with hybrid_opt=2: the levels are WRF’s mass-level eta (ZNU) with 1.0 for the surface, and the offset is WRF’s model top P_TOP in hPa. HYSPLIT’s prfcom sends a flag-5 file to prfwrf only when the file has MUBA and MUPE and hybrid_wrfvcoords.txt sits beside it; otherwise metini treats it as flag 1 and prfsig integrates heights between the PRES levels. WrfAxis files follow that prfsig path exactly as sigma files with PRES do (vertical._hysplit_z_agl and the column in ops/sample.py); on two HRRR columns written as flag-5 files they agree with the compiled prfsig within 0.007 hPa.

Module imports#

Runtime imports between modules (TYPE_CHECKING imports left out; lazy means inside a function body):

vertical, exceptions, _io, _time        no arlmet imports
grid           (pyproj)
packing      → _pack (C extension), grid
header       → _time, exceptions, grid
index        → _time, exceptions, grid, header, vertical
record       → exceptions, grid, header, packing, vertical; lazy: xarray
collection   → grid, record, vertical
recordset    → collection, grid, header, index, record, vertical
file         → _time, collection, exceptions, grid, header, index, record,
               recordset, vertical, xarray.backends.CachingFileManager;
               lazy: ops.sample, ops.subset, xarray.dataset
ops.subset   → _io, exceptions, file, grid, header, index, packing, record, vertical
ops.sample   → _time, grid, vertical; lazy: file
ops.concat   → exceptions, file
xarray.*     → _io, _time, grid, ops.subset, vertical; lazy: file
archives     → _time; lazy: fsspec, ops.subset

file imports the operations and the Dataset builder lazily because they import file. archives is not imported by import arlmet, and imports fsspec only when it downloads.

Memory tests#

tests/test_memory.py measures the writers with tracemalloc: the peak during extract_subset() (both the byte-copy path, without a bbox, and the repack path, with one) and write_dataset() (including from a lazy Dataset), and what is still held after they return with the garbage collector disabled. Its grids are about 200x200, so array buffers dominate Python object overhead.

Python sizes each open file’s buffer from the filesystem’s st_blksize. On a filesystem with a large block size (some network filesystems report 128 KB, where a local disk reports 4 KB) each open file adds that much, and three of these tests fail. Run them with the temporary directory on a local disk.

Examples in the docs#

The user guides run their examples when the docs are built (just build-docs, as CI does), so they show real output and the build fails when one breaks. There is no sample ARL file in the repository, and an example never downloads one, so docs/_ext/docs_examples.py writes small files of made-up values with arlmet.write_dataset(). A page that reads a file starts with a block that is run but not shown:

.. ipython:: python
   :suppress:

   import os

   import docs_examples

   docs_cwd = docs_examples.temp_workdir()
   docs_examples.sample_file("met.arl")

temp_workdir() changes to a new temporary folder, so the examples can write files with short names, and the page ends with another such block, os.chdir(docs_cwd). sample_file() takes the valid times, and upper=False for surface variables only or projected=True for a Lambert grid. A few things to know:

  • An expression is echoed only at the top level of a block: print one inside a with or for.

  • A block that raises or warns fails the build, unless it has :okexcept: or :okwarning:.

  • All pages share one session, so each page imports what it uses.

  • An example that downloads stays a plain code-block, and its page says so.

Benchmarks#

Use real files from the archives for performance work, for example the July 2024 NCEP/NCAR Reanalysis month:

from arlmet.archives import get_archive

get_archive("reanalysis").fetch("2024-07-01", "2024-07-01", dest_dir="met/")

This gives RP202407.gbl (73x144, 124 times, 18 levels). Measured on one development machine, extract_subset() took about 2.1 s for bbox=(-170, 10, -40, 70) (repack path) and about 0.3 s for levels=[0, 1, 2, 3, 4] without a bbox (byte-copy path). A 614x428 NAM12 day (get_archive("nam12")) took about 0.27 s for the same levels.
