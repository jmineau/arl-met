Converting Other Models’ Output#

HYSPLIT reads only ARL files, and NOAA publishes them for a few products (HRRR, NAM, GDAS, GFS, …; see Downloading Archived Meteorology). For any other model, HYSPLIT ships one Fortran data2arl program per product. arlmet.converters holds Python versions of them, and converters for products HYSPLIT has none for. Each takes the product’s own output, opened with xarray, and returns a Dataset in the layout arlmet.write_dataset() writes: ARL’s four-character names, the units HYSPLIT reads, rows from south to north, and the vertical axis HYSPLIT expects for the product. You can look at it, plot it and change it before anything is written.

The converters so far:

  • arlmet.converters.from_era5(): ECMWF’s ERA5 reanalysis on pressure levels, as HYSPLIT’s era52arl converts it, and on its model levels, as HYSPLIT’s api2arl converts ECMWF’s hybrid levels.

  • arlmet.converters.from_gfs(): NCEP’s GFS forecasts and GDAS analyses on pressure levels (pgrb2 files), as HYSPLIT’s api2arl converts them.

  • arlmet.converters.from_icon(): DWD’s ICON-EU and ICON-D2 forecasts on their regular lat/lon grids and pressure levels, which HYSPLIT has no converter for.

  • arlmet.converters.from_wrf(): WRF-ARW output (wrfout files) on its own grid and model levels, as HYSPLIT’s arw2arl converts it.

ERA5#

Download the pressure-level and single-level fields from the Copernicus Climate Data Store, for example with its cdsapi client (an account and API key are needed). Ask for the same hours and area in both:

import cdsapi

client = cdsapi.Client()
when = {
    "product_type": ["reanalysis"],
    "year": ["2024"],
    "month": ["07"],
    "day": ["18"],
    "time": [f"{hour:02d}:00" for hour in range(24)],
    "area": [44, -116, 38, -110],  # north, west, south, east
    "data_format": "netcdf",
}
client.retrieve(
    "reanalysis-era5-pressure-levels",
    {
        **when,
        "variable": [
            "geopotential", "temperature", "u_component_of_wind",
            "v_component_of_wind", "vertical_velocity", "relative_humidity",
        ],
        "pressure_level": ["1000", "975", "950", "925", "900", "850", "800",
                           "700", "600", "500", "400", "300", "250", "200"],
    },
    "era5_pressure_levels.nc",
)
client.retrieve(
    "reanalysis-era5-single-levels",
    {
        **when,
        "variable": [
            "surface_pressure", "geopotential", "2m_temperature",
            "2m_dewpoint_temperature", "10m_u_component_of_wind",
            "10m_v_component_of_wind", "boundary_layer_height",
            "total_precipitation", "surface_sensible_heat_flux",
            "surface_latent_heat_flux", "surface_solar_radiation_downwards",
        ],
    },
    "era5_single_levels.zip",
)

Open both with xarray. A single-level netCDF request that mixes instantaneous fields with accumulated ones (precipitation, the fluxes) comes as a zip of two files; open each and merge them. chunks={} keeps the values on disk until they are written, one time step at a time:

import xarray as xr

pressure_levels = xr.open_dataset("era5_pressure_levels.nc", chunks={})
single_levels = xr.merge(
    [
        xr.open_dataset("data_stream-oper_stepType-instant.nc", chunks={}),
        xr.open_dataset("data_stream-oper_stepType-accum.nc", chunks={}),
    ],
    compat="override",
)

How it differs from era52arl#

The values are what HYSPLIT reads, which is not always what era52arl writes:

  • geopotential becomes height through ECMWF’s gravity, 9.80665 m s-2 (era52arl multiplies by 0.102);

  • the hourly totals of the heat fluxes and the downward solar radiation become W m-2 by dividing by 3600 s (era52arl multiplies by 0.00028, so its DSWF is 0.8 % high);

  • total cloud cover TCLD is in percent, as HYSPLIT reads it (era52arl writes the 0 to 1 fraction);

  • the heat fluxes SHTF and LHTF are positive upward, as HYSPLIT takes them: its stability routine (stbanl.f) reads a positive SHTF as the ground heating the air, and HYSPLIT changes the sign only for NAM’s ETA files (prfcom.f). ERA5’s fluxes, and era52arl’s, are positive downward, so HYSPLIT reads a sunny afternoon in an era52arl file as a stable surface layer;

  • the latent heat flux is named LHTF, which HYSPLIT reads (era52arl names it LTHF).

As era52arl does, it writes a DIFW record after each WWND and a DIFR record after TPP1, which keep what 8-bit packing leaves out.

What it does not do#

  • The ensemble (a number dimension) and forecast-step layouts (a step dimension): each raises ValueError. Select one ensemble member, or the valid times, first.

  • Regridding: the converter writes the grid the input is on, which must be a regular latitude/longitude grid.

ERA5 on model levels#

ERA5’s own vertical grid is 137 hybrid sigma-pressure levels, which follow the terrain near the ground: model level 137 is about 10 m above it. HYSPLIT reads them as its hybrid levels (vertical flag 4), which is what from_era5() writes when the first Dataset is on model levels. The Climate Data Store serves them from ECMWF’s archive as reanalysis-era5-complete, in GRIB, with a request in MARS’s keywords:

client.retrieve(
    "reanalysis-era5-complete",
    {
        "class": "ea", "expver": "1", "stream": "oper", "type": "an",
        "date": "2024-07-18", "time": "00:00:00/to/23:00:00",
        "levtype": "ml", "levelist": "80/to/137",
        "param": "130/131/132/133/135",  # t, u, v, q, w
        "grid": "0.25/0.25", "area": "44/-116/38/-110",
    },
    "era5_model_levels.grib",
)

Open it with cfgrib, which names the level dimension hybrid, and pass the single-level fields of the same hours, which must include the surface pressure sp: HYSPLIT finds each level’s pressure from it.

model_levels = xr.open_dataset(
    "era5_model_levels.grib",
    engine="cfgrib",
    backend_kwargs={"filter_by_keys": {"typeOfLevel": "hybrid"}},
)
ds = arlmet.converters.from_era5(model_levels, single_levels)

Each ARL hybrid level is one number, as HYSPLIT’s api2arl writes it: a pressure offset in whole hPa plus a sigma, so that the level’s pressure is offset + sigma * surface pressure (model level 120 is 29.881). Two limits of that format decide which levels can be written:

  • The offsets of the levels above about model level 24 (near 5 hPa) round to the same whole hPa, so from_era5 refuses them and names the first. Keep levels 24 to 137, or fewer.

  • The index record at the start of each time step lists every level’s variables and must fit in one record of nx * ny bytes, so a small crop holds fewer levels: a 61 x 61 cell grid holds about 60 levels of five variables. arlmet.write_dataset() says when it does not fit.

The level is written in six characters, so where its offset is 100 hPa or more its sigma keeps two decimals, and HYSPLIT reads some mid-troposphere levels up to about 5 hPa from ERA5’s pressure. api2arl’s files are rounded the same way.

GFS and GDAS#

NOAA publishes GFS and GDAS as ARL files (Downloading Archived Meteorology), but only some of them: the 0.25 degree GFS on its own hybrid levels, the 1 degree GDAS on pressure levels. from_gfs() converts NCEP’s GRIB2 pgrb2 files themselves, so any cycle, forecast hour or resolution (0.25, 0.5 or 1 degree) can be written on pressure levels. NOAA keeps them in a public bucket, https://noaa-gfs-bdp-pds.s3.amazonaws.com, one file per cycle and forecast hour:

gfs.20250901/00/atmos/gfs.t00z.pgrb2.0p25.f003     GFS, 0.25 degree, 3-hour forecast
gdas.20250901/00/atmos/gdas.t00z.pgrb2.1p00.f000   GDAS, 1 degree, analysis

Open each file with cfgrib (pip install cfgrib eccodes), which splits a GRIB2 file into one Dataset per kind of level, and pass all the Datasets of all the files together:

import cfgrib

files = ["gdas.t18z.pgrb2.1p00.f006", "gdas.t00z.pgrb2.1p00.f000"]
datasets = [ds for f in files for ds in cfgrib.open_datasets(f)]

Each valid time becomes one time step. An analysis has no precipitation or fluxes, which a forecast accumulates or averages over its hours, so where two files hold a field at the same valid time the shorter forecast is used: above, the 00 UTC analysis gives the instantaneous fields and the 18 UTC cycle’s 6-hour forecast the precipitation and fluxes, as NOAA’s GDAS ARL files are made. GFS empties its precipitation bucket every 6 hours (a 3-hour forecast holds hours 0 to 3, a 6-hour forecast 0 to 6), which is what HYSPLIT reads in TPP6. Here made-up Datasets laid out as cfgrib returns them stand in for those two files:

The API page of from_gfs() lists the GRIB2 variables it converts. All the pressure levels of a file are written; to write fewer, select them first, in the Dataset that holds gh (d.sel(isobaricInhPa=[1000, 925, 850, 700, 500, 300, 200])). NCEP’s planetary boundary layer height is a local GRIB2 parameter that ecCodes reads as unknown, so PBLH is not written, and the GDAS files’ instantaneous total cloud cover is missing at every point, so they give no TCLD. Like api2arl, it writes no DIF* records.

ICON#

DWD’s ICON-EU (Europe, about 6.5 km) and ICON-D2 (Germany, about 2.2 km) are published free at https://opendata.dwd.de/weather/nwp/, each forecast on its own grid and on a regular lat/lon grid; from_icon() converts the lat/lon files on pressure levels. DWD keeps a forecast for about a day. Each file holds one variable at one level and one forecast step, compressed with bzip2:

icon-eu/grib/00/t/icon-eu_europe_regular-lat-lon_pressure-level_2026110600_003_850_T.grib2.bz2
icon-eu/grib/00/tot_prec/icon-eu_europe_regular-lat-lon_single-level_2026110600_003_TOT_PREC.grib2.bz2
icon-eu/grib/00/hsurf/icon-eu_europe_regular-lat-lon_time-invariant_2026110600_HSURF.grib2.bz2

The pressure-level variables are fi, t, u, v, omega and relhum; the API page of from_icon() lists the single-level ones it reads. Download those you need for every step, unpack them (bunzip2) and open each with cfgrib, passing all the Datasets together:

import glob

import cfgrib

files = sorted(glob.glob("icon-eu_europe_regular-lat-lon_*.grib2"))
datasets = [ds for f in files for ds in cfgrib.open_datasets(f)]

The levels of each variable are stacked, and each valid time becomes one time step. ICON’s precipitation and surface fluxes are totals and means from the start of the forecast (a 3-hour file holds hours 0 to 3); each is written as the total or mean since the step before. TPP1 is that precipitation per hour, so 3-hourly steps (ICON-EU’s after 78 hours) give the hourly mean of each 3 hours. A forecast’s step 0 has no such interval, so its precipitation and fluxes are missing records; as in from_gfs(), where two forecasts hold a field at the same valid time the shorter step is used, so the first 6 hours of each run joined together give every time step its fields. ICON’s fluxes are positive downward; SHTF and LHTF are written positive upward, as HYSPLIT takes them. ICON’s own grid (icosahedral, the only one DWD publishes for global ICON) and its model levels (heights that follow the terrain, which no ARL vertical coordinate describes) are not converted: remap the output to a lat/lon grid and pressure levels first (for example with CDO) and write it as GRIB2 with DWD’s variable names. HYSPLIT has no ICON converter to compare with; the files written are read by HYSPLIT’s hycs_std.

WRF#

from_wrf() converts WRF-ARW’s wrfout netCDF files on the model’s own grid (Lambert conformal, polar stereographic or Mercator) and levels, as arw2arl does with its default variables. Open the files of one run together, joined along Time, so that each hour’s precipitation can be taken from the run’s accumulated totals:

import xarray as xr

wrf = xr.open_mfdataset(
    "wrfout_d01_2013-06-30_*", combine="nested", concat_dim="Time"
)

The file has source AWRF, which HYSPLIT reads as WRF. It keeps WRF’s staggered winds where WRF puts them, UWND on the west and VWND on the south face of each cell, and HYSPLIT (and arlmet.sample_points()) read them there. WWND is WRF’s vertical velocity as a pressure tendency (hPa s-1), and TPP1 the precipitation since the time step before, per hour, each with a DIF* record. The first time step has no precipitation, as arw2arl writes it when it has no earlier file.

Converted alongside arw2arl from the same four hours of a 12 km WRF run, every field matched its file but the two it computes, TEMP and WWND, which differ in the last bits of single precision, as Fortran’s and NumPy’s arithmetic do: TEMP mostly by 1e-4 K, and by one packing step (0.125 K) at 0.006 % of its values; WWND by at most 6e-5 hPa s-1. arw2arl keeps the lowest 50 levels unless told otherwise; all are kept here, and ds.isel(level=slice(0, 50)) keeps fewer.

A run made with do_avgflx_em = 1 also writes winds averaged over each output interval and coupled to the column mass (AVGFLX_RUM, …), which arw2arl -c2 converts (NOAA’s notes on its own WRF ARL files say HYSPLIT did slightly better with them in limited testing). winds="averaged" writes those instead, as stored, with the fields HYSPLIT decouples them with (MUU0, MUV0, MSFT, MSFU, MSFV); arlmet.sample_points() decouples them too, while arlmet.open_dataset() returns the stored values:

In [33]: averaged = arlmet.converters.from_wrf(wrf, winds="averaged")

In [34]: averaged["UWND"].attrs  # mass-coupled, as stored
Out[34]: {'units': 'Pa m s-1'}

In [35]: sorted(set(averaged.data_vars) - set(ds.data_vars))
Out[35]: ['MSFT', 'MSFU', 'MSFV', 'MUU0', 'MUV0']

arw2arl’s TKE list is not converted.
